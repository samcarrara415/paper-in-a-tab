What runs where

The server
The team ported Paper 26.2 down to Java 8 with ~30 patches and a bytecode rewriter. This remake side‑steps the entire pipeline: Paper 1.8.8 already is Java 8, so the stock jar runs after one 30‑line bytecode patch that removes the TCP listen a browser can't do.
The runtime
CheerpJ compiles a JVM to WebAssembly and JavaScript. It fetches the jars over HTTP, mounts an IndexedDB‑backed filesystem at /files, and runs a small launcher whose four native methods are implemented in the page's JavaScript — that's the console and file manager bridge.
The world
A flat world with the Nether and End switched off, so first generation takes seconds instead of minutes — that's also what lets this boot on a phone. Every chunk you change is saved back to browser storage and is still there tomorrow.

About this remake

The original experiment is by Lodeway Labs, built by a team: a Java 8 port of modern Paper, a custom netty transport, and a tunnel backend. This page is an AI's from‑scratch remake of the same idea in one session, built to run from static hosting and to boot on a mobile browser. Same trick, different trade‑offs: they carried modern Paper into the browser; this build picks the Paper that already fit.
